# Cs⁺(H₂O)ₙ, n = 4–14 — воспроизводимый расчётный проект

**Статус поставки:** 11 наборов входных сферических упаковок, исходный код, драйвер, дневник и пустой шаблон таблицы. **Настоящие вычисления Cs⁺ ещё не выполнялись.** Ни одна энергия, структура минимума или координационное число не выдуманы.

## 1. Научная постановка

Цель — систематический поиск и анализ локальных минимумов Cs⁺(H₂O)ₙ с n = 4–14 (11 стехиометрий), исследование распределения фактического координационного числа и появления молекул воды за пределами первой оболочки. В сравнительном ряду Li⁺ → Na⁺ → K⁺ → Rb⁺ → Cs⁺ цезий представляет предел большого радиуса и низкой плотности заряда при одинаковом заряде +1. Для отдельного кластера CN=n не гарантируется даже при большом ионе.

| Параметр | Основное значение |
|---|---|
| Ион | Cs⁺; заряд +1; мультиплетность 1 |
| Метод | GFN2-xTB/ALPB(water), xTB 6.7.1 (фактическую сборку записывать) |
| Основная серия | n=4…14; по 100 независимых GWH-стартов, всего 1100 |
| Сферические упаковки | `inputs/Cs_04`…`Cs_14/packing.vecfle`; их SHA256 в `inputs_manifest.csv` |
| Стартовое расстояние | 3,33 Å = кристаллический радиус Cs⁺ 1,81 Å (Шеннон, КЧ6) + условные 1,52 Å для O |
| GWH | `zyz` (нижний регистр), центрирование WaterCharges, ограниченные опорные точки |
| После GWH | свободная оптимизация `normal` → `tight` → Hessian; **без смещений по мнимым модам** |
| Проверка минимума | внутренние ν > 0 см⁻¹, после исключения 6 внешних мод; граничные значения проверять, не принимать автоматически |
| Группировка | CoCoS только после свободной оптимизации; `--CritFreq 125` см⁻¹ как предварительный повышенный критерий; сравнение 83,4/125/166,8 и зеркального совмещения |
| Координационный анализ | MDAtomLocalEnvironment: `--RunWaterAnalysis --DoNotUseRounding --scale 1.` |
| Полная первая оболочка | предварительный операционный критерий `0 ≤ n - #water ≤ 0,15`; 5,9 при n=6 проходит, 5,5 требует геометрической проверки и не классифицируется как полная оболочка по *этому* порогу |
| Чувствительность КЧ | отдельная проверка отсечек 0,05 / 0,10 / 0,15 / 0,20 / 0,30; геометрические Cs–O/Cs–H критерии — только независимая диагностика |

**Важно:** 3,33 Å задаёт расстояние до *опорных точек GWH/центров зарядов молекул воды*, не обязательно расстояние Cs–O. Радиус исходной геометрии не переносится в окончательную характеристику оболочки. Порог по дробному `#water` указан явно для воспроизводимости и является предварительным операционным решением, а не универсальным физическим определением КЧ. Не изменять порог, чтобы искусственно получить `КЧ=n`.

```text
│   ├── Cs_04/ ... Cs_14/          # 11 входных packing.vecfle

│   ├── cs_assemble.py             # общая сводка, графики, итоговый архив
│   ├── validate_cs_shell.py       # независимая геометрическая проверка
│   └── export_workbook.py         # Excel по проверенным CSV

```

Все 11 каталогов расчётов находятся внутри `runs` и не смешиваются. `__pycache__`, временные файлы и неудачные расчёты не считаются научными результатами. Пробный набор `runs/Cs_04/smoke_3` отделён от `full_100` и не добавляется к основной сотне.

## 4. Запуск из терминала Cursor (Windows)

Извлеки проект в отдельную папку (например, на рабочий стол) и открой **корень проекта** в Cursor. Установи Python 3.11+, зависимости и исполняемый xTB:

```powershell
py -m pip install -r requirements.txt
xtb --version
py tests\selftest.py
py scripts\cs_pipeline.py check
powershell -NoProfile -ExecutionPolicy Bypass -File .\runs\full_100_driver.ps1
```

Если полный путь включает кириллицу/OneDrive и xTB не принимает такой путь, создай при необходимости короткую ссылку в Windows (не вторую копию):

```powershell
New-Item -ItemType Junction -Path 'C:\cshyd' -Target (Get-Location).Path
Set-Location C:\cshyd
powershell -NoProfile -ExecutionPolicy Bypass -File .\runs\full_100_driver.ps1
```

**Один запуск** автоматически проводит короткий реальный пилот (`smoke_3`), затем n=4–14 последовательно с полным циклом. Перед запуском на Windows он проверяет, не занят ли xTB другими тяжёлыми задачами, и не завершает чужие процессы. Драйвер держит блокировку от второго запуска, сохраняет успешные промежуточные результаты, повторяет сбойную стадию, затем пытается пройти нерешённые этапы повторно. Если причина принципиальная (неверная программа, несовместимый формат, нехватка места), она должна быть исправлена в Cursor; фиктивная успешность запрещена.

Посмотреть состояние, не запуская второй процесс:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\runs\full_100_driver.ps1 -Status
powershell -NoProfile -ExecutionPolicy Bypass -File .\runs\full_100_driver.ps1 -DryRun
```

После обработки вычислений можно только пересчитать анализ готовых геометрий: `py scripts\cs_driver.py --analysis-only`. Это **не** повторяет GWH и xTB.

## 5. Проверяемые результаты

Для каждого `runs/Cs_XX/full_100/` сохраняются три файла **только ограниченной стадии GWH**: `constrained_100_multiframe.xyz`, `constrained_100.zip`, `energies.csv`. Должно быть ровно 100 согласованных XYZ и реальных энергий. `free/` хранит независимую свободную оптимизацию и Hessian для каждого старта; `verified/` — геометрии без подтверждённых мнимых внутренних мод; `cocos/` — группы структур и `command.json` с `CritFreq`; `cocos_stability/frequency_sensitivity.csv` — число групп при 83,4/125/166,8 см⁻¹; `unique_minima/` — **все** неэквивалентные минимумы; `mdatom/` — фактические `.res` и таблицы `radius[A]`, `cos(x)`, `#water`; `final/` — подмножество с почти полным КЧ по заявленному критерию; `shell/` — геометрический контроль. Отклонённые геометрии не исчезают бесследно: их причины сохраняются в журналах.

После каждого завершённого состава пополняются `EXPERIMENT_LOG.md` и `runs/MDAtom_water.xlsx` (столбцы: `n`, структура, энергия в Ha, радиус, cos(x), дробный #water). В терминале показываются `E=... Ha`, `νmin=... см⁻¹`, число групп и КЧ. Дневник содержит действительную методику, параметры, времена, распределения КЧ, проверки, ошибки и научные выводы; без выдуманных чисел.

После полного цикла: `Cs_SUMMARY.csv`, `README_RESULTS.md`, `analysis/lowest_energy_shell_model_per_n.csv`, `analysis/boltzmann_E_only_300K.csv`, графики, XYZ, CSV и **один** `Cs_hydration_results.zip`. Основная единичная характеристика для каждого n берётся от наиболее низкоэнергетического представителя с полной оболочкой. Больцмановское среднее по электронным энергиям при 300 K — **только сравнительная оценка**, не равновесные населённости раствора; без корректных термохимических данных нельзя выдавать оценки на основе ZPVE, H(300 K), G(300 K) за выполненные.

**Перед сдачей:** проверить общее количество стартов 1100, корректность зарядов, суммарный состав Cs₁OₙH₂ₙ, сходимость всех оптимизаций, реальные Hessian и 3N−6 внутренних мод, полное сопоставление CoCoS/MDAtom, отсутствие дубликатов, корректность первого и второго слоя и целостность архива. Если часть расчётов отклонена как не минимум или не найдены структуры с первой оболочкой, честно показывать это отдельно, а не подставлять нули.
